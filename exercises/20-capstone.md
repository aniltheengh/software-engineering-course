# Exercises 20 — Capstone milestones

These are deliverables, not practice problems. Complete them in order and commit each one.

### 1. Proposal
One page: the problem, who has it, what the software will do, and three things it will deliberately not do.

### 2. Requirements
Ten to twenty user stories with acceptance criteria, ranked must-have, should-have and could-have.

### 3. Design document
Architecture diagram, data model, main interfaces, the technology choices and one decision record for each significant choice.

### 4. Walking skeleton
The thinnest end-to-end slice running through every layer, with CI building and testing it. Nothing useful yet, but everything connected.

### 5. Must-have features
Every must-have story implemented with tests written alongside. Keep a changelog.

### 6. Hardening
Run the Module 15 security checklist against it, load-test or profile the slowest path, and handle every failure you can provoke.

### 7. Release
A tagged version that is deployed or installable, with a README a stranger can follow from clone to running.

### 8. Retrospective
One page: what went well, what you would do differently, what you learned, and what you would build next.
